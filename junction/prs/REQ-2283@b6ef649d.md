### What the agent did and decided
Claude Code 2.1.323 · claude-opus-5-5 · 29 turns · 42 recorded steps · run `REQ-2283-20261114-054453`

The crash comes from Roslyn importing private instance fields of value types from metadata (needed for struct layout), including compiler-generated auto-property backing fields such as <Key>k__BackingField. Unlike source symbols these are not IsImplicitlyDeclared, so TypeCollector.GetObjectInfo's field loop treated them as un-keyed members and indexed DeclaringSyntaxReferences[0], which is empty for metadata symbols. The fix skips fields that cannot be referenced by name and replaces the two remaining direct [0] indexers with FirstOrDefault(). A regression test emits the library to a PE image and references it as metadata (a project reference would keep source symbols and not reproduce the bug). It covers record struct and struct and checks that the consuming assembly gets a GeneratedMessagePackResolver with no diagnostics. The full MessagePack.SourceGenerator.Tests suite passes (169/169).

| Decision | Why | Confidence |
|---|---|---|
| Skip fields with !CanBeReferencedByName in the [Key]-mode field loop | Compiler-generated backing fields from metadata are not marked IsImplicitlyDeclared. Without this skip, using FirstOrDefault alone would stop the crash but could still report a MemberNeedsKey error with no location against the consuming project (when the struct has non-public keyed members), which would break the clean build the requirement asks for | sure |
| Replace DeclaringSyntaxReferences[0] with FirstOrDefault() at the MemberNeedsKey (field) and BothStringAndIntKeyAreNull (property) sites | Matches the neighbouring helpers and removes the remaining crash paths for symbols without syntax. Source-declared types get the same location as before | sure |
| Reproduce with a PE image (MetadataReference.CreateFromImage) instead of AdditionalProjects | AdditionalProjects creates compilation references whose symbols still have DeclaringSyntaxReferences, so the existing Generics_Defined_In_ReferencedProject test cannot catch this bug | sure |
| Generate expected resource files by temporarily enabling WRITE_EXPECTED, then reverting it | This is the repo's existing workflow for snapshot outputs; I checked the generated ItemFormatter<T> by hand and it serializes only Key | sure |
