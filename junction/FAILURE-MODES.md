# Failure modes we saw

Every entry below happened while building or running the reference on the four sample branches.

## In the review engine

| # | What went wrong | Effect | Status |
|---|---|---|---|
| 1 | Tests in MessagePack reach the generator through a framework (`CSharpSourceGeneratorVerifier<MessagePackGenerator>`, then Roslyn calls `Initialize`). The call graph had no edge for either step. | Receipt claimed "no test reaches" every changed member in #2283, #2234 and #2297. A false alarm, which teaches owners to ignore the claim. | Fixed: edges through generic type arguments, and "dispatch" edges from a type to its overrides and interface implementations. |
| 2 | Lines-to-read counted whole member spans. `GetObjectInfo` is 700 lines long. | "Owner reads 753 of 228 changed lines." The headline number was nonsense. | Fixed: count only changed lines inside each listed member. |
| 3 | Git puts a tab after file names that contain spaces in `---`/`+++` headers. | 21 generated files looked like outliers with empty edits. | Fixed: strip the tab, disable path quoting. |
| 4 | Compiled T4 templates carry an `<auto-generated>` header. | They were cleared as generated snapshots, so the real logic of #2297 vanished from the read list. | Fixed: a `.cs` paired with a `.tt` is a template. |
| 5 | The silencing check is a keyword list. | It caught #2283 only because the agent's doc comment says "dropped here". The same change without the comment passes. | Open. Documented as a limit. |
| 6 | Requirement-to-test tracing uses word overlap between requirement lines and test names. | Weak: "has a matching test" can be true for an unrelated test. | Mitigated: always labelled "heuristic", never "verified". Unmatched lines become refusals. |
| 7 | A static path from a test to a member does not mean the test checks its behaviour. | "Reached by a test" can be true while the change is untested in practice. | Open. Next step is a mutation probe: revert the member, rerun its tests, expect a failure. |
| 9 | New expected-output snapshots (`.g.cs` added under tests) were treated as edits to generated code. | The agent's own #2283 fix was flagged "generated files changed in non-uniform ways". | Fixed: added generated files under tests count as test fixtures. |
| 8 | 1.8% of call edges are resolved by name only (no semantic binding). | Possible false paths. | Mitigated: shown dashed in the graph and marked `name-only`. |

## Missed by the engine, found by a human

| Branch | What the engine missed |
|---|---|
| #2297 | The generated attribute is wrapped in `#if !NETSTANDARD2_0 && !NETFRAMEWORK`, so consumers on .NET Standard 2.0 or .NET Framework get no `[ExcludeFromCodeCoverage]`. The requirement says "all generated code". The engine verified the edit was uniform; it could not tell that the uniform edit is incomplete. Owner to verify whether the guard is needed. This is the kind of miss that should be recorded as an escape and tracked per area. |

## In the agent-written changes (found by the engine)

| Branch | Finding |
|---|---|
| #2283 | `ReportIfLocatedInCompilation` is wired into every diagnostic the type collector reports, not only the crashing path. Diagnostics without a source location in the compilation are now dropped. The requirement does not ask for that. Refused; routed to owner. |
| #2234 | A test file outside the requirement's declared scope (`tests/MessagePack.SourceGenerator.ExecutionTests`). |
| #2129 | 12 public API members added, including a new public attribute. API shape refused; routed to owner and maintainers. |
| #2297 | 221 of 222 generated snapshots carry an identical 3-line edit; 1 also has an unrelated reformat. Only the outlier is sent to a human. |
