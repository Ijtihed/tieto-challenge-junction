### What the agent did and decided
Claude Code 2.1.323 · claude-opus-5-5 · 46 turns · 65 recorded steps · run `REQ-2283-20261113-194944`

Fixed IndexOutOfRangeException in TypeCollector.GetObjectInfo for closed generic structs from referenced assemblies. Roslyn imports private (compiler-generated backing) fields of metadata value types; the field loop tried to report MemberNeedsKey via DeclaringSyntaxReferences[0], which is empty for metadata symbols. Such fields declared on the formatted type are now skipped, and the property BothStringAndIntKeyAreNull path uses FirstOrDefault. Generator and analyzer tests using a real in-memory metadata reference fail without the fix and pass with it; the full SourceGenerator test suite (171) passes.

| Decision | Why | Confidence |
|---|---|---|
| Skip the MemberNeedsKey/AOTDerivedKeyAttribute diagnostic for fields declared on the formatted type when the field has no syntax, instead of reporting it with a null location | MemberNeedsKey is Error severity; reporting it with no location for a compiler-generated backing field of a metadata type would turn a crash into a spurious build-breaking error that the consumer cannot act on | ⚠️ unsure |
| Keep the inherited-member branch (BaseTypeContainsUnattributedPublicMembers) unchanged by placing the skip inside the ContainingType==formattedType branch | Source types deriving from metadata base classes rely on that diagnostic, which is located on source base-type syntax | sure |
| Replace DeclaringSyntaxReferences[0] with FirstOrDefault() in the property BothStringAndIntKeyAreNull diagnostic | Same crash class for metadata properties with [Key(null)]; matches neighbouring helpers; source behaviour unchanged | sure |
| Add ReferencesHelper.CompileToMetadataReferenceAsync to build a PE image reference for tests | AdditionalProjects uses compilation references whose symbols keep syntax, so it does not reproduce the bug | sure |
