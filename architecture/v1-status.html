Schema v1.0

A working end-to-end architecture intelligence product. Here's what it does and why it matters.

The Problem Schema Solves

Every AI coding tool (Cursor, Copilot, Cline, Claude Code) works with text. Schema works with architecture. When a staff+ engineer asks "where is auth handled?" or "what would break if I change this API?" — the AI currently guesses. Schema gives it a verified graph to reason about instead.

Before Schema

  • AI reads raw files, guesses at architecture
  • PR reviews are vibes — "LGTM" on 2000-line diffs
  • No one knows when the architecture drifts
  • Invented API calls pass code review undetected
  • "Where is X?" requires 20 minutes of grep

After Schema

  • AI queries a typed graph of your real architecture
  • Every PR gets a machine-verified review comment
  • Weekly drift reports surface architectural decay
  • Hallucinated APIs are flagged with "did you mean?"
  • "Where is X?" returns ranked evidence in <30ms

What Schema Actually Does (End-to-End)

1. You install it in 2 minutes

Schema is an MCP server. It plugs into Cursor, Claude Code, Cline, or Continue. No account, no cloud, no API key. One npm install + a 3-line config in your editor's mcp.json.

2. You ask a question → Schema answers from the graph

When you type "where is authentication handled?" in Cursor, Schema's graph.ask action fires:

1
Your question hits graph.ask via MCP
<1ms
2
BM25 lexical search across all symbols + file names
~5ms
3
Graph traversal walks architectural neighbours
~10ms
4
Reciprocal Rank Fusion combines both signals
<1ms
5
Top-K ranked nodes returned as evidence
25ms total

Schema returns evidence. Your AI synthesises the answer. Schema never has merge authority — it's an advisor, always.

3. Every PR gets a review comment — automatically

A GitHub Action fires on every push to a PR. Schema diffs the graph, evaluates architectural rules, detects hallucinated API calls, and posts a sticky comment. No manual step.

1
PR push triggers .github/workflows/schema.yml
2
Schema extracts the graph + diffs against the base
~600ms
3
Rules evaluate · hallucinated APIs flagged · semantic diff classified
~90ms
4
667-line review comment posted (or previous one updated)
sticky

The comment includes:

SectionWhat it tells you
Semantic summaryIs this a real change or mechanical noise? (high_impact / low_impact / semantic_noop)
Changed filesFull list with +/- line counts
Rule violationsArchitectural rules broken by this PR, with deep links to the atlas
Hallucinated APIsFunctions called in the diff that don't exist in the graph — with BM25 "did you mean?" suggestions
Atlas linkOne click to the visual atlas with the PR's changes highlighted

4. Weekly drift reports surface architectural decay

Every Monday, a cron job runs drift.generate and opens a PR with the drift report. Four sections:

SectionWhat it catches
Areas grown / shrunkClusters that gained or lost significant nodes
New cross-cluster depsDependencies that didn't exist last week
Deprecation candidatesNodes that lost most of their callers
Rule-violation trendAre violations increasing or decreasing over time?

If nothing changed substantively, the cron skips silently. No noise.

5. The visual atlas shows your architecture in real time

Studio is a React canvas that renders your codebase as a typed graph at three zoom levels:

LevelWhat you see
L0 · ArchitectureClusters with shape badges (Service / Domain / Library) + ★ entry-point hints
L1 · ModulesFiles within a cluster, grouped by folder
L2 · DetailFunctions, classes, routes — every extractable symbol
